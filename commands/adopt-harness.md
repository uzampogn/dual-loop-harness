# Adopt the dual-loop harness

Set up the current repo for the dual loop. Copy from `${CLAUDE_PLUGIN_ROOT}/templates/` (outside the repo, so the first read prompts once — approve it); never overwrite existing user content without saying so first. This command is interactive: it needs a human for the prompts and for step 6.

1. **Preflight.** Confirm cwd is a git repo root (`git rev-parse --show-toplevel` equals cwd; otherwise stop and say where to cd). Check tools: `bd`, `jq`, and `gh` or `glab` — report anything missing and how to install it. Warn if the working tree is dirty: `bd init` (step 5) must run on a clean tree.
2. **State folders.** If `dual-loop-brain/` or `contracts/` exists, stop and report — adoption is already done or conflicts. Else copy `templates/dual-loop-brain/` and `templates/contracts/` into the repo root, then delete the example item from the live queue: `dual-loop-brain/02-backlog/00-example-metric-drawer/` and `dual-loop-brain/03-build-reports/00-example-metric-drawer/`, and strip the example rows from `dual-loop-brain/02-backlog/BACKLOG.md` (keep the empty table header). Append to `.gitignore` (create it if missing): `.claude/settings.local.json` (personal overrides) and `.beads/lanes/` (live-lane sentinels — machine-local, never shared).
3. **Settings.** No `.claude/settings.json`? `mkdir -p .claude && cp` the template in. Exists? Merge in: the `enabledPlugins` entry, the `permissions.allow`/`deny` lists, preserving everything the user already has — show the diff before writing. Every write under `.claude/` is permission-gated (Write, Edit, and shell alike): expect 1 prompt, and never use a comment key such as `_comment` — the settings schema rejects unknown fields. Explain the file in your report instead: `enabledPlugins` enables the harness (and optional playwright — add the official marketplace first or drop the entry); `permissions.defaultMode` is `auto` so workers run unattended (auto mode's classifier approves routine work and refuses destructive actions; `deny` still binds); `permissions.allow` pre-approves your stack's routine tools ahead of the classifier (add yours; keep the deny list); `AskUserQuestion` is denied by design so design sessions interview in plain Q&A; personal overrides go in the gitignored `settings.local.json`, never here — repo-level `enabledPlugins` travels into worker worktrees.
4. **CLAUDE.md.** Append `templates/CLAUDE-snippet.md` to the end of the repo's `CLAUDE.md` (create the file with a 1-line `# CLAUDE.md — <project>` heading first if it doesn't exist). Skip if a `## Dual-loop harness` section is already there. Touch nothing else in the file — stack, test commands, and layout are the user's; if they are missing, say so in the report (workers read them).
5. **Queue.** Commit steps 2–4 first, then run `bd init` on the clean tree. Warning (bd 1.1.x): it may append a managed block to CLAUDE.md, write `AGENTS.md`/`.agents/`/`.codex/`, write or rewrite `.claude/settings.json` (a bare `{"hooks": {}}` if it was missing), and auto-commit. Cleanup if so: `git reset --soft HEAD~1`; delete `AGENTS.md`, `.agents/`, `.codex/`; strip the managed CLAUDE.md block; re-check `.claude/settings.json` still carries `enabledPlugins` + `permissions` and restore it from step 3 if not (a bare `"hooks": {}` key bd adds is harmless — leave it). Keep `.beads/` and the `.gitignore` lines bd added.
6. **Seed shared state.** Ask the user for their 3 most-settled decisions (stack, deploy target, visual direction) and append them to `dual-loop-brain/00-decision-log.md` as D1–D3. Nobody to ask (headless run)? Skip, and list this as pending in the report.
7. **Report.** Print what was created/merged and the first-run sequence: `/dual-loop:create-observations` → `/dual-loop:design-session` → `/dual-loop:build-session`.
